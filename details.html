METHOD NOTES

Algorithm and assumptions

Open a note whenever a step feels surprising.

01 What does this graph represent?

A filled detector vertex is a syndrome event: a parity check disagreed with the expected result. An edge represents an elementary error mechanism with those detection endpoints.

This is a small, unit-cost teaching graph for one error type. It does not include time, measurement faults, error correlations, or the full geometry of a physical code.

The decoder receives the syndrome, not the hidden error. Its job here is to choose an edge set with the same measured endpoint parity.

02 Why do odd clusters grow?

Inside an ordinary region, every edge contributes two endpoints. An odd number of syndrome events therefore cannot be explained entirely inside that region. Growth searches for another defect or an allowed boundary.

active = odd parity AND no allowed boundary

Defects determine parity; all member vertices determine union-by-size. Those counts answer different questions.

MergeNew parity
odd + oddeven → pause
odd + evenodd → grow
even + eveneven → pause

A boundary flag overrides the growth rule. A boundary-valid cluster can absorb an odd syndrome without becoming active.

03 What fills a half-edge?

During a round, each active endpoint contributes up to ½ of an edge. Two growing endpoints can fill an untouched unit edge in one round. One growing endpoint needs two rounds.

0 + ½ + ½ = 1   ·   ½ + ½ = 1

Contributions are capped at the remaining capacity. Every edge completed in the round enters the fusion queue. Process that queue before deciding which clusters grow next.

The round is synchronous: an earlier Union changes the roots used by later queue entries, but it does not retroactively change that round’s growth.

04 Why are there two kinds of forest?

The Union-Find forest stores set membership. Find follows parent pointers; path compression points visited vertices directly to the root. Union attaches the smaller set’s root to the larger set’s root.

The peeling forest is built from real, fully grown graph edges. It removes cycles so that leaves can be processed. A parent-pointer link is not automatically an eligible correction edge.

“Breadth-first” and “depth-first” change this second forest only. Compare their costs while the syndrome and grown support stay fixed.

05 Why is peeling forced at a leaf?

A non-root leaf has one remaining tree edge. If its residual bit is 1, selecting that edge is the only way to clear it. If its bit is 0, discard the edge. Remove the leaf and repeat.

At an ordinary root, the component’s even parity guarantees the final bit is 0. At an allowed boundary root, there is no measured bit to satisfy. With several boundary vertices, this demo builds a forest with a separate root at each one.

The residual panel checks r = s ⊕ ∂C at every step. At completion, all measured residuals must vanish.

06 How does this relate to Blossom?

The TUM Blossom animation teaches maximum-cardinality matching through alternating paths and odd-cycle contraction. In quantum decoding, a related minimum-weight matching formulation seeks a correction of minimum total cost.

Union-Find follows a different procedure: expand invalid regions, merge them, then peel a forest. It does not maintain a matching or perform Blossom’s alternating-path optimization.

This lab’s exact reference uses shortest paths and a small subset dynamic program for at most 12 defects. It is a correctness baseline on this toy graph, not an implementation of Sparse Blossom.

07 Why can the cost exceed the minimum?

There are two separate restrictions. Growth may exclude every globally optimal correction. Then the forest can discard useful cycle edges from the grown region.

global minimum ≤ grown-region minimum ≤ forest correction

Example 4 isolates a forest-choice cost. Example 5 isolates a growth-region cost. The Compare tab reports all three quantities and can overlay a globally optimal correction.

Matching a syndrome does not establish logical success. That also depends on the actual error and the code’s logical operators, which this graph does not model.

08 Which implementation choices matter?

This lab uses uniform half-edge growth, union by vertex count, path compression, deterministic edge ordering, and your selected graph forest. These choices make each step reproducible.

Union by size, prioritizing clusters by frontier size, and assigning likelihood-based edge weights are different choices. Only the first is implemented here.

The production algorithm’s almost-linear bound relies on efficient frontier and set data structures. This teaching engine scans edges and copies snapshots for playback; its execution time is not a performance benchmark.
